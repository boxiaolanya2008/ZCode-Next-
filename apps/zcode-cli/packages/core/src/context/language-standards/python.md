# Python 编码规范

> 适用于 Python 工程。用户需求模糊时,先按本规范明确假设与验收标准,再实现。

## 1. 风格与命名

- 遵循 PEP 8:类用 PascalCase,函数/变量/方法用 snake_case,常量用 UPPER_SNAKE_CASE,私有成员可用单下划线前缀。
- 缩进统一 4 空格;在新增/修改文件时与项目既有风格(rst/gray 之类)保持一致。
- 中文注释;代码保留英文标识符。

## 2. 类型与文档

- 为公开函数/Signature 标注类型注解(`def f(x: int) -> str:`),模块级类型用 `typing` / `TypeAlias` 表达意图。
- 编写 doctstring(一行摘要 + 参数/返回 + 副作用),让结构与意图自解释。
- 区分 `Optional[T]`(可空)与默认缺省;不要用 `Any` 逃避类型检查,确需时收窄到 `object` 后显式转换。

## 3. 结构与架构

- 导入顺序:标准库 → 三方 → 本地;避免循环导入。
- 单文件 ≤ 400 行;职责按模块/包拆分,避免大文件堆职责。
- 业务逻辑与 I/O 分离:网络/文件/子进程/环境变量收敛到 adapter 或基础设施层。
- 状态唯一所有者,避免全局可变单例带来的多写路径。

## 4. 错误处理

- 使用具体的异常类型,不要裸 `except:`(会吞掉 `KeyboardInterrupt`/`SystemExit`);确需兜底时 `except Exception` 并记录上下文。
- `raise ... from e` 保留链式原因;自定义异常继承合适基类并提供结构化字段。
- 只在边界做防御性校验;不为不可能发生的失败堆分支。

## 5. 异步与并发

- 用 `async/await` 与 `asyncio`;并发独立任务用 `asyncio.gather`(默认 return_exceptions=False)并处理好各自的取消/超时。
- 注意 GIL 与 CPU 密集、IO 密集选型:CPU 密集用并发进程(`ProcessPoolExecutor`),不要用线程伪装并行。
- 共享资源访问用锁/信号量,避免用 sleep 掩盖竞态。

## 6. 构建 / 测试 / 工具

- 以仓库工具为准(pytest 之类),行为变更先补测试。
- 依赖与虚拟环境、版本锁定以仓库 `pyproject.toml` / `requirements` 为准;不引入未使用依赖。
- 大体积结果不直接灌回上下文,落盘后返回摘要与路径。

## 7. 常见陷阱

- 可变默认参数 `def f(x=[])` 导致的共享状态。
- 整数除法 `/` 与整除 `//`、`0.1+0.2` 浮点误差。
- 深浅拷贝、内存泄漏(全局缓存、未关闭文件/连接用上下文管理器 `with`)。
