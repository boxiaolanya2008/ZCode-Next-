# Shell / Bash 脚本规范

> 适用于 shell 脚本(命令行、CI、运维)。用户需求模糊时,先按本规范明确目标 shell 与跨平台边界,再实现。

## 1. 目标与头信息

- 明确 shebang(`#!/usr/bin/env bash` / `sh`)、`set -euo pipefail` 开启严格模式(根据目标环境,如 macOS bash 3.2 注意语法降级)。
- 脚本开头给注释说明用途、参数与退出语义;中文注释,命令保留英文。

## 2. 健壮性

- 始终给变量加引号 `"$var"`;用 `${var}`、参数扩展处理缺省与默认值;避免未加引号的通配符闲差。
- 外部命令路径/调用用参数数组(`"$@"`)避免 shell 注入;解析用户输入要谨慎对待字符串。
- 依赖 shell 特性前做能力检测(如 `command -v`),不假设目标全支持。

## 3. 跨平台

- 三平台(macOS/Linux/Windows)差异:路径分隔符、环境变量大小写、`.cmd`/`.exe`、参数转义、换行符。
- 用 `mktemp`/`$TMPDIR` 处理临时目录;避免硬编码绝对路径与 shell 特异性语法。

## 4. 错误与退出

- 每个失败外部命令显式判断退出码并给出可读错误消息;`trap` 处理清理与信号。
- 脚本不作为普通函数静默吞错;数据与结果可追踪,日志与调试路径不泄露敏感信息。

## 5. 结构 / 可维护

- 函数化而非一次性长脚本;参数解析(如 `getopts`)集中;保持 ≤ 400 行、分割文件重复使用。

## 6. 调试 / 测试

- `bash -x`/`set -x` 用于排查;为可测行为抽离函数并用断言;CI 中验证关键路径。

## 7. 常见陷阱

- 空格分隔的词拆分与 glob 展开;`[[ ]]` 与 `[ ]`、`&& / ||` 优先级。
- `while read` 的子 shell 作用域、管道丢失退出码。
