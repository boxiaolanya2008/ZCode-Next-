# C++ 编码规范

> 适用于 C++ 工程(系统、图形、高性能、桌面)。用户需求模糊时,先按本规范明确边界与标准(如 C++17),再实现。

## 1. 风格与命名

- 类型用 PascalCase,成员函数/变量遵循结构化命名,常量用 UPPER_SNAKE_CASE;缩进与花括号风格随项目。
- 优先使用标准与教学有据命名;中文注释,代码保留英文标识符。
- 头文件 guard + `namespace`;避免在头文件里未必要地暴露实现。

## 2. 现代 C++ 与资源管理

- 使用 RAII 管理资源;智能指针 `std::unique_ptr`/`std::shared_ptr` 明确所有权,原始指针仅用于非拥有的观察。
- 优先值语义与移动(`std::move`),复制昂贵时显式移动;避免裸 `new/delete`(除非确需)。
- 用 `std::string_view`/`ranges`/结构化绑定/`auto` 表达意图;默认不可变用 `const`。
- 容器访问注意迭代器失效与悬垂引用。

## 3. 类型与安全

- 固定宽度整数用 `<cstdint>`;明确有符号/无符号与溢出语义。
- 用 `nullptr` 而非 `NULL`/`0`;区分空/缺省语义。
- 弱化隐式拷贝陷阱:禁止多态的深拷贝歧义,用 `virtual` 析构器或 `std::unique_ptr` 持有接口。

## 4. 错误处理

- 用异常(内建或业务异常)与错误码:常规可恢复失败倾向返回 `std::expected`/错误码,编程错误用异常或断言尽早失败。
- 只在有能力处理的边界捕获;不吞异常;保留 cause 上下文。
- 输入校验在接口边界做,尽早失败。

## 5. 并发

- 用 `std::async`/`std::jthread`/`std::atomic`/`std::mutex` 组织;共享状态唯一 owner。
- 避免数据竞争与死锁:明确临界区范围与锁顺序;不用 sleep 掩盖同步。
- 可等待与取消语义显式传播。

## 6. 构建 / 测试 / 工具

- 以仓库构建系统(CMake/premake 之类)为准;开启并满足严格警告。
- 行为变更补测试(Test 等);依赖确认许可证与来源。

## 7. 常见陷阱

- 未定义行为(悬空、UB)与整数溢出;`final`/显式删除来避免多态错误调用。
- 隐式拷贝/移动导致资源双释放;模板导致的二进制膨胀与编译错误信息长。
- 循环引用与异常安全(goto cleanup 不可用,依赖 RAII)。
