# Go 编码规范

> 适用于 Go 工程(服务端、CLI、系统工具)。用户需求模糊时,先按本规范明确边界,再实现。

## 1. 风格与命名

- 遵循 Go 惯例:`gofmt` 是唯一风格来源;命令式空行、导出/未导出标识符(大写/小写开头)语义不得误用。
- 命名短小:包名小写单数;方法/函数动词开头;不用 `get` 前缀(直接 `Name()` 即可)。
- 中文注释;代码保留英文标识符。导出标识符必须有文档注释(以标识符名开头)。

## 2. 错误处理

- Go 惯例:显式错误返回;不在函数内吞错。`if err != nil { return ..., fmt.Errorf("context: %w", err) }` 用 `%w` 包裹保留原因。
- 避免 `errors.Is`/`errors.As` 之外的错误文本判断;用哨兵错误或错误类型区分。
- 应用逻辑错误与不可恢复错误分开处理;panic 只用于程序不变量被破坏,绝不用于常规错误流。
- 尽早 return;避免深嵌套 if-err 金字塔。

## 3. 并发

- 用 goroutine + channel + `context.Context` 组织并发;不要在 goroutine 里泄漏后台循环。
- 用 `sync.WaitGroup`/`sync.Once`/`sync.Mutex` 保护共享状态;`sync.Mutex` 不要拷贝(用指针持有)。
- 用 errgroup 并发收集错误并传播取消;明确取消传播路径,不用超时掩盖同步问题。
- 避免在 goroutine 中访问父作用域可变变量导致的竞态;通过参数/通道传递。

## 4. 结构与架构

- 单文件 ≤ 400 行;按包拆分职责,避免大文件堆职责。
- 业务逻辑与 I/O 分离;网络/存储/系统调用收敛到接口/基础设施层,便于测试。
- 依赖注入优于全局变量;跨模块经公开接口交互,避免循环依赖与内部实现深挖。
- 序列化契约(JSON/Protobuf)有明确 schema,边界做运行时校验。

## 5. 资源与内存

- 使用 `defer file.Close()`/`defer resp.Body.Close()` 释放资源;注意 defer 的执行位置与循环内放 catch 语义。
- 大切片用索引/迭代避免拷贝;区分切片底层数组的别名语义。
- context 传递链完整;不创建不相关的子 context 丢弃父链路。

## 6. 构建 / 测试 / 工具

- 以仓库工具与 `go.mod`/Makefile 为准;行为变更先补 `_test.go`(table-driven)。
- 格式化 `gofmt`,静态检查按仓库规则执行。

## 7. 常见陷阱

- 循环变量捕获 goroutine 闭包(旧版本必须先复制变量)。
- map 不保证顺序;并发读写 map 直接 panic。
- `nil` 接口判空陷阱(typed nil);defer 中修改返回值需要命名返回值。
