# C 编码规范

> 适用于 C 工程(底层、嵌入式、系统)。用户需求模糊时,先按本规范明确边界与移植目标,再实现。

## 1. 风格与命名

- 类型/结构体用 PascalCase 或前缀 `_t`,函数用小写下划线(如 `foo_bar`),宏用 UPPER_SNAKE_CASE。
- 缩进/花括号风格与项目既有代码一致;中文注释,代码保留英文标识符。
- 头文件有 include guard(`#ifndef`/`#pragma once`),命名避免冲突。

## 2. 内存与安全

- 显式管理所有权:谁分配谁释放,释放后置 NULL;用 RAII 或统一释放 helper 减少泄漏路径。
- 边界检查优先:计算长度时用 `snprintf`/`strlcpy`/`memcpy_s` 等安全函数或显式长度校验,避免缓冲区溢出。
- 谨慎使用指针运算;数组/索引访问做必要越界分析。
- 资源(文件句柄、锁、malloc)在每条错误路径上释放,用 goto cleanup 或单一出口集中收口。

## 3. 类型与可移植性

- 固定宽度整数用 `<stdint.h>`(`int32_t`/`uint8_t`),不用依赖机器字长的 `int`/`long`。
- 明确无符号/有符号与溢出语义;不依赖实现定义的位移与对齐假设。
- 字符串与字节数组区分,`sizeof` 与 `strlen` 语义勿混淆。
- 常量用 `const` 表达只读意图;指针参数按只读/只写标注。

## 4. 错误处理

- 通过返回错误码并显式判断错误是否传递;不静默吞错。
- 错误码稳定且可归类;调用方基于错误码而不是错误文案做流程判断。
- 函数先校验输入参数(空指针、越界),尽早失败。

## 5. 并发(如需)

- 明确锁/原子粒度;共享状态唯一 owner;死锁与竞态通过清晰序与有限临界区避免。
- 信号处理只做最小动作(置标志量),不在信号处理器里调用非 async-signal-safe 函数。

## 6. 构建 / 测试 / 工具

- 以仓库构建系统(CMake/Makefile)为准;启用严格警告(`-Wall -Wextra -Werror` 视目标)。
- 行为变更补测试;修复 bug 用中文注释说明原因与依据。

## 7. 常见陷阱

- 缓冲区/格式串参数错位;`sizeof` vs `strlen`;字符串字面量只读。
- 整数提升与有符号无符号混用;`NULL` 与 '0' 混淆。
- 内存泄漏/悬空指针/use-after-free。
