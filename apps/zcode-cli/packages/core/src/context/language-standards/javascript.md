# JavaScript 编码规范

> 适用于 JavaScript 工程(浏览器、Node.js)。用户需求模糊时,先按本规范做假设澄清与明确约定,再写代码。

## 1. 风格与命名

- 中文注释;代码保留英文标识符。布尔量 `is/has/should` 前缀,函数用动词短语,常量用 UPPER_SNAKE_CASE。
- 使用现代语义:模块用 ESM(`import/export`);过程式脚本如需要才用 CJS,勿混用造成兼容问题。
- 句末分号一致(随仓库 `package.json` / 格式化器设置),缩进一致,首选项目现有格式。

## 2. 变量与作用域

- 优先 `const`,仅确实需要重绑定时用 `let`;禁止 `var`。
- 顶层避免隐式全局;浏览器里避免给 `window` 追加没有命名空间的挂载。
- 解构赋值、对象展开、可选链 `?.`、空值合并 `??` 优先于手写判空;注意 `||` 与 `??` 的差异(`??` 只跳过 null/undefined)。

## 3. 相等与类型判定

- 一律用严格相等 `===` / `!==`。
- 判定类型使用明确的守卫:`typeof` 处理原始值,`Array.isArray` 处理数组,`instanceof` 处理对象;不要用 `==` 或依赖隐式转换。
- 区分缺省(`undefined`)与显式 `null`;`foo &&` / `foo ||` 优先级陷阱易错,优先显式判断。

## 4. 异步

- 使用 async/await;对相互独立操作使用 `Promise.all` 并处理任一拒绝。
- 事件监听器记得移除;定时器/句柄要清理,避免泄漏与幽灵回调。
- 不在循环里去 await 创建并发副作用而忽视竞态;规定执行顺序时要显式串行。

## 5. 错误处理

- 抛出真实 `Error`(可带 name/cause),不要返回 null/undefined 作为唯一失败信号再让调用方猜。
- 捕获后若不能恢复,向上抛或仅在有能力处理的边界捕获;不吞错。
- 浏览器全局错误与 Node `unhandledRejection` 要给可观测出口。

## 6. 可读性与约定

- 函数短小、单一职责;文件 ≤ 400 行,超出拆模块。
- 命名自文档化,不写仅解释"在做什么"的注释;注释只表达代码无法自证的约束/原因。
- 外部 I/O 收敛到 adapter;业务逻辑不直接散落 `fetch`/`fs`/`child_process`/`process.env`。

## 7. 常见陷阱

- `Array.prototype.forEach` + async 不会等待;`sort` 默认按字符串排序数字会出错。
- 深浅拷贝、共享引用修改、`Math.max(...arr)` 对超大数组的栈溢出。
- TDZ(暂时性死区)、提升与块级作用域。
