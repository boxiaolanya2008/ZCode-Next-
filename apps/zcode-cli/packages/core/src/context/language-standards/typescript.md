# TypeScript 编码规范

> 适用于 TypeScript 工程(含 React/Node 前后端)。用户需求模糊时,先按本规范澄清假设、约定清晰边界,再落代码。

## 1. 风格与命名

- 统一中文注释;代码保留英文标识符。命名自解释:`布尔量用 is/ has/ should` 前缀;`函数用动词短语`。
- 类型用 PascalCase,变量/函数/方法用 camelCase,常量用 SCREAMING_SNAKE_CASE(仅用于模块级不可变字面量)。
- 不使用隐式 any;确实无法推断时给显式类型或 `unknown` + 收窄,禁止 `as any` 绕过类型检查。
- 文件内顺序:引入 → 类型声明 → 常量 → 函数 → 导出;类型先于其使用。

## 2. 类型系统

- 能用 `type` 表达联合/交叉/映射/工具类型时用 `type`,能用 `interface` 表达可扩展对象契约时用 `interface`,不要混用制造读者负担。
- 对外契约(跨模块/进程/协议边界)优先用 `zod` schema 做运行时校验,而非仅靠 TS 类型;类型作为 schema 的静态投影。
- 区分"可选"(可能不存在)与"可空"(显式 null),不要混用 `foo?` 与 `foo: T | null`。
- 用 readonly / 联合字面量 / 泛型约束表达意图;禁止 `any`/`@ts-ignore`/`@ts-expect-error` 掩盖问题。
- 类型收窄使用可判别联合 + `switch`,避免一层层 `as` 强转。

## 3. 结构与架构

- 单文件默认 ≤ 400 行;超过必须按高内聚低耦合拆分,不要用大文件堆职责。
- 分层:入口/UI 只做呈现与编排;业务逻辑表达意图;I/O(网络、文件、子进程、环境变量)收敛到 adapter 或基础设施层。
- 跨包、跨模块通过显式有限接口交互;禁止绕过公开入口深挖实现细节,禁止循环依赖。
- 状态只保留在唯一所有者;避免多写路径与重复状态,明确数据流方向与幂等边界。

## 4. 错误处理

- 错误是一等对象:让错误向上冒泡到有能力处理的层;不在低层吞错只打日志。
- 使用结构化错误(类型/错误码/上下文),不要靠错误文案做流程判断。
- throw 时保留原始原因并补充上下文;不要丢失调用链。
- 仅在不变量可能被违反的边界做防御,不要为不可能发生的场景堆兜底。

## 5. 异步与并发

- 一律 async/await;避免裸 promise 链与回调嵌套。
- 需要并发但相互独立时使用 `Promise.all`;需要在 Exec 等沙箱内并发时要考虑运行时边界,不要盲目并行冲突。
- 超时/取消/信号语义要显式;绝不靠 sleep 掩盖同步问题。
- 共享可变状态需唯一 owner;跨 async 回调不要隐式依赖闭包里的旧值。

## 6. 构建 / 测试 / 工具

- 以仓库实际命令为准:typecheck / lint / 测试入口按目标包 `package.json`。
- 行为变更先补测试;修复 bug 用中文注释说明原因与依据。
- 不引入未使用依赖;引入第三方代码需确认许可证与来源。

## 7. 常见陷阱

- `===`/`!==` 而非宽松比较;区分 `null == undefined` 的语义陷阱。
- 数组/对象 `forEach` 里 async 不会等待;遗漏 `const` 捕获旧值导致闭包陷阱。
- readonly 数组/元组用 `as const` 时留意推断范围。
