# Ruby 编码规范

> 适用于 Ruby 工程(Rails、纯 Ruby、CLI)。用户需求模糊时,先按本规范明确边界与环境(版本、bundler),再实现。

## 1. 风格与命名

- 类/模块用 PascalCase,方法/变量用 snake_case,常量用 UPPER_SNAKE_CASE;布尔方法以 `?` 结尾,破坏性方法以 `!` 结尾(仅当配套非破坏版本)。
- 缩进 2 空格;遵循 Ruby Style Guide;中文注释,代码保留英文标识符。

## 2. 类型与安全

- Ruby 是动态类型,尽量用清晰命名、`#type` 化与最小接口;用 `nil` 显式表达缺省。
- 严格使用 `==`/`eql?` 语义;避免隐式 `to_s`/类型转换造成混淆。
- 用不可变常量表达共享配置,但避免全局可变状态。

## 3. 风格与惯例

- 熟练掌握 block/procs/lambdas;集合枚举(`each/map/select`)优先于手写循环。
- 符号化字符串键一致性;适时使用关键字参数(`**kwargs` 已废弃),用显式关键词参数提升可读性。
- 避免方法不可控的副作用;方法单一职责。

## 4. 错误处理

- 用具体异常类(`begin/rescue/ensure`)区分失败原因;不要裸 `rescue StandardError` 吞错。
- 只在有能力恢复的边界捕获,保留导致异常的原因(`raise ... from`)。
- `ensure` 用于清理资源;避免在 `ensure` 里覆盖主异常。

## 5. 并发与可观测性

- 用线程/进程判明并发;Rails 常用进程 fork 与线程池;共享状态用互斥或基于 actor 的分池。
- 不依赖系统级 sleep 掩盖竞态;明确超时与重试语义。

## 6. 结构 / 构建 / 测试

- 单文件 ≤ 400 行;任何 I/O 都收敛到服务/适配层,回调避免深嵌套。
- 以仓库 Gemfile / bundler 为准;行为变更补测试(RSpec/Minitest)。

## 7. 常见陷阱

- block 的分号与优先级、`tap` 误用、符号未释放/内存泄漏。
- 集合修改时枚举、`nil.` 链式空错误。
