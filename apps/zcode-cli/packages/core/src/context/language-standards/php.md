# PHP 编码规范

> 适用于 PHP 工程(Web、CLI、Composer 包)。用户需求模糊时,先按本规范明确运行时版本(>=8.x)与目标框架,再实现。

## 1. 风格与命名

- 类/接口/枚举用 PascalCase,方法/变量/属性用 camelCase,常量用 UPPER_SNAKE_CASE,目录/命名空间映射清晰。
- 缩进以仓库 `.php-cs-fixer`/PSR-12 为准;中文注释,代码保留英文标识符。
- 严格类型声明:文件头 `declare(strict_types=1);`。

## 2. 类型与空值

- 启用严格模式,充分利用声明式类型提示:`int`/`string`/`bool`/`array`/对象及可空 `?T`。
- 用 `?:`/`??`(`null-coalescing`)与空安全处理缺省;避免松散 `==` 与隐式类型转换陷阱。
- 大量使用联合类型、可为空与位域场景的 `enum`。

## 3. 对象与架构

- 依赖注入优于静态单例与 `global`;使用构造函数注入。
- 业务逻辑与 I/O(DB 通过 PDO/ORM、HTTP、文件、环境)分离,收敛到 service/repository。
- 使用接口/抽象定义契约;避免循环依赖与耦合实现细节。

## 4. 错误处理

- 用异常(带结构化字段)表达失败,`try/catch/finally` 恢复或向上抛;不吞 `\Error`。
- 业务失败用自定义异常类型区分;错误信息不泄露敏感细节。

## 5. 并发与可观测性

- PHP-FPM 请求模型按请求作用域;并发/异步任务按目标(如 Swoole 等)需明确选型与生命周期。
- 避免依赖长为单位的时间 sleep 解决竞态;明确重试/退避。

## 6. 构建 / 测试 / 工具

- 以仓库 Composer 为准;行为变更补测试(PHPUnit/Pest);运行静态分析与格式检查。
- 避免引入未使用依赖,确认许可证。

## 7. 常见陷阱

- 松散比较与类型转换;隐式 `true` 为真值判断导致逻辑错误;数组键的字符串/整数自动转换。
- 变量作用域(函数/方法内的 $this vs 全局)与未初始化变量。
