# C# 编码规范

> 适用于 C# 工程(.NET,含 ASP.NET、桌面、云)。用户需求模糊时,先按本规范明确边界与目标框架,再实现。

## 1. 风格与命名

- 类型/接口(`I` 前缀)/方法用 PascalCase,局部变量/参数用 camelCase,常量用 PascalCase(随 .NET 惯例)。
- 缩进以 `.editorconfig`/仓库格式为准;中文注释,代码保留英文标识符。
- 属性与字段语义清晰;字段超过构造函数明确设默认。

## 2. 类型与空值

- 启用 nullable reference types:`string?` 明确可空,避免隐式空引用传播。
- 优先使用不可变/只读类型与 `record`(值语义比较);数据模型与 DTO 分开。
- 使用类型化的泛型集合与 `IEnumerable<T>` 惰性;序列化/协议契约用 schema 并在边界校验。

## 3. 并发与异步

- 全链路 async/await;同步阻塞异步上下文的坑点(不要 `.Result`/`.Wait()`,会死锁)。
- 并发独立任务用 `Task.WhenAll`;资源(IO/HttpClient/DB)用 `using`/`await using` 处理。
- `HttpClient` 作为订阅/单例共享而非每次新建;明确取消令牌 `CancellationToken` 传播。
- 关键内存/并发配置与连接数语义按框架最佳实践。

## 4. 错误处理

- 异常按类型区分失败原因;业务异常带结构化字段;可恢复与不可恢复边界清晰。
- 捕获后能恢复才捕获,保留内层异常;不吞异常。
- `try/finally`/`using` 统一资源;异步异常用 `try-catch` 包 await。

## 5. 结构与架构

- 单文件 ≤ 400 行;按命名空间/程序集拆分职责,避免上帝类。
- 依赖注入(DI)优于静态单例;业务逻辑与 I/O(EF/HttpClient/文件)分离收敛到 repository/adapter。
- 显式接口契约;避免循环依赖与内部实现深挖。

## 6. 构建 / 测试 / 工具

- 以仓库 `csproj`/`sln` 为准;行为变更补测试(xUnit 等)。
- 启用并满足分析器警告;不引入未使用依赖。

## 7. 常见陷阱

- 异步上下文死锁/资源泄漏;字符串与字符串池、`==` 语义。
- LINQ 惰性求值与多次枚举;`DateTime` 时区与精度;集合并发修改。
